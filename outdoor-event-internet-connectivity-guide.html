DTW Field Notes · Connectivity

Outdoor event internet and broadcast connectivity: plan for event day, not an empty venue.

A speed test during setup is useful, but it is not a complete broadcast network plan. Crowds, distance, terrain, shared infrastructure, RF congestion, routing, and failure tolerance all matter.

Separate camera transport from internet delivery

Two different network problems often get called “internet.” The first is moving camera, audio, comms, timing, or control data around the venue. The second is delivering the final program to a streaming platform or remote partner. They can share infrastructure, but they should be designed and tested as separate requirements.

Start with wired infrastructure when it exists

Dedicated fiber or Ethernet with known routing and ownership is usually easier to predict than a shared public Wi-Fi network. Ask who controls the network, whether ports or VLANs can be reserved, what upstream path is available, and whether event-day traffic changes the service.

Bandwidth is not the only metric

A stream needs stable upload throughput, but latency, jitter, packet loss, routing changes, firewall rules, and congestion can create problems even when a speed test shows a large number. Test the actual encoder path and destination when possible. For practical upload-speed targets and headroom guidance, see What Internet Speed Do You Need to Livestream an Event?

Cellular performance can change when the crowd arrives

An empty venue may have excellent mobile data. Thousands of phones can change that quickly. Bonded cellular can improve resilience by combining carriers or paths, but it should still be treated as engineered connectivity rather than guaranteed capacity.

Point-to-point links need real line-of-sight planning

Wireless bridges can be effective for long field paths, but trees, terrain, buildings, moving equipment, mounting height, interference, weather, and safe installation all matter. A map alone cannot prove a radio path.

Fiber solves distance, not every operational problem

Fiber is excellent for long, high-bandwidth links, but production still needs connector protection, routing, strain relief, safe crossings, conversion, spares, and a way to diagnose faults. Temporary events should document every long path so strike and troubleshooting remain controlled.

Build primary and backup paths around consequence

Not every show needs two complete internet systems. The right redundancy depends on what happens if the stream stops. Paid broadcasts, sponsor-heavy shows, ticketed remote viewing, or contractual deliveries may justify more separation than a low-risk internal stream.

Protect the control network

Production switching, camera control, comms, timing, graphics, intercom, and device management may depend on IP even when the final stream uses a different uplink. Keep production-critical traffic organized, documented, and isolated from unnecessary public traffic where practical.

Test with a failure drill

Before air, deliberately ask what happens if the primary uplink disappears. Does the encoder fail over? Does someone have to move a cable? Does DNS or routing change? Does the stream reconnect automatically? The first time the crew learns the answer should not be during the event.

The DTW Broadcast Planning Checklist includes connectivity alongside power, cameras, replay, crew, and delivery so the network plan is part of the full production scope.
